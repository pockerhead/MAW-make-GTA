## Проект

Экспериментальный проект: однопользовательский экшен от третьего лица по мотивам серии GTA, который строят MAW-агенты. Владелец задаёт вектор и принимает feel/визуал, код пишет пайплайн.

**Стек:** Rust + Bevy целиком (ECS, рендер, звук, ввод). Godot и других движков нет. Bevy на момент старта — 0.19.x; точная версия пинится первой задачей с кодом, дальше источник правды — `Cargo.lock`.

**Стадия:** pre-design. Кода нет, диздока нет. Пока диздок в `docs/design/` не помечен владельцем как `APPROVED`, ни одна механика не закон.

**Донор:** предыдущий Bevy-проект владельца, указатели локально (gitignored): @.claude/local/donor.md

## Critical Invariants

Нормативная версия для агентов — `maw/project-context/README.md` и `domains/*.md`. Здесь кратко, для главной сессии:

- **Headless-first:** геймплей работает и тестируется в headless Bevy `App` (`MinimalPlugins` + наши плагины, та же функция сборки, что у игры). Рендер, камера, UI, звук — потребители геймплейного состояния, не владельцы.
- **Bevy API не вспоминать, а сверять** с исходником пиненной версии в `~/.cargo/registry/src/*/`. Bevy ломает API каждый минор, в памяти моделей версии перемешаны.
- **Каждая система — это кадр.** Тяжёлое и unbounded — в `AsyncComputeTaskPool` (Requested → InFlight → Ready → apply) или тайм-слайс. `FixedUpdate` для геймплея и физики, `Update`/`PostUpdate` для презентации; `just_pressed` внутри `FixedUpdate` не читать.
- **Data first:** тюнинг (скорости, камера, урон, кулдауны) — в `assets/<домен>/*.ron`, закон (тик, масштаб, слои коллизий) — `const` в коде. Новый `const` под тюнинг = блок на ревью.
- **Domain-driven:** `player/`, `vehicle/`, `camera/`, `combat/`, а не `systems/`/`components/`. Плагин на домен. Файл < 750 строк warning, < 950 hard limit.
- Golden Path (let-else, early return, вложенность < 2), YAGNI, хирургические правки, комментарии только "почему".

## Вес пайплайна = цена ошибки

Перед задачей одной строкой назвать цену ошибки. "Сломается молча и всплывёт через месяц" (порча состояния, бюджет кадра, сейвы, туннелирование на скорости) → полный доказательный слой. "Владелец увидит на первом кадре" (feel камеры, управление, анимация, визуал) → механика + один честный гейт + прогон владельца. Отказ добавлять машинерию — валидная находка. Урок прошлого проекта: гейт хорошо держит уже понятое от тихой поломки, а новое находят запуск и глаз.

## Inline Paired Mode (дополняет MAW)

Первый вопрос развилки: виден ли гейт headless?
- Да (тест, предикат) → MAW автономен.
- Нет (камера, feel, управление, анимация) → сначала инлайн с глазом владельца, потом MAW для кода. Не гонять feel-фичу через дорогой полный прогон до того, как владелец её пощупал.

Перед тем как писать код инлайн, самому загрузить то, что MAW-имплементер получает инъекцией: `.claude/agents/maw-implementer-<effort>.md` (generic-роль, pre-flight), `maw/project-context/agents/implementer.md`, `maw/project-context/README.md` и домены задачи.

## Maw Pipeline

`maw` — adversarial multi-agent pipeline над доской `maw/tasks/{pending,in_progress,done,blocked}/`. Режимы: `full`, `small-fix`, `brainstorm`, `deep-research`.

Базовый пайплайн — generic upstream (`pockerhead/maw`, ставится `install.sh`), ноль проектной специфики. Всё знание проекта живёт в `maw/project-context/` и инжектится оркестратором в спавны. Правится через `/maw-context`, никогда руками в `.claude/skills/`.

Тела MAW-скиллов сюда не импортируются (они большие, Skill-тул грузит их при вызове). Любой вход в пайплайн — `Skill(maw-execute-task)` первым шагом, заведение задач — `maw-tasks`, правки контекста — `maw-context`. Протокол оркестратора по памяти не исполнять.

### Planning artifacts — три роли, не путать

- **`maw/ROADMAP.md`** — только граф зависимостей pending-задач, генерируется из `task.md ## Dependencies`. Руками не править, прозу не дописывать.
- **`docs/narrative-graph.md`** — вектор: North Star, что берём следующим и почему. Руками.
- **Notebook** — впечатления и уроки, не статус и не план.

**После каждой закрытой задачи обязательно** актуализировать `docs/narrative-graph.md`: вычеркнуть сделанное, сдвинуть порядок, проверить, что North Star всё ещё верна. Если приоритет неясен — спросить владельца про видение, не угадывать.

**Там же, после каждой закрытой задачи**, синхронизировать с реальностью `README.md` (разделы "Статус", "Запуск", "Что строим") и раздел "Проект" этого файла (стадия, стек, пиненная версия Bevy, команды сборки). Устаревший статус в README — баг, а не косметика.

### Формы знания

| Класс | Форма | Где |
|---|---|---|
| Геймдизайн (что есть в игре) | Диздок | `docs/design/*.md` |
| Архитектурный выбор ("выбрали X, потому что Y") | ADR | `docs/decisions/ADR-NNN-*.md` |
| Как работает подсистема | Design note | `docs/architecture/*.md` |
| Правило со шрамом из продакшена | Инвариант | домен в `maw/project-context/domains/` |
| Уроки, эмоции, процесс | Notebook | `~/.claude/projects/D--test-gta-like/memory/` |

Инварианты без шрамов — карго-культ. Новый доменный модуль появляется, когда есть реальный прецедент и грепабельный триггер.
