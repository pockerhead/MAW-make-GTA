# PLAN_V2 — TASK-007 / T6 shooting

## 1. Review notes

**Disconfirmation tested first.** A sustained left mouse press with a pistol is the most concrete case that would falsify this plan. `TASK_FINAL.md` resolves Q3 to **B**: pistol and shotgun fire once per press, SMG fires while held. `PLAN.md` C2 uses `fire_held || fire_requested` for every gun, and §4.7 and Q3 still choose automatic fire for all guns. No weapon system exists yet in `crates/gta_sim/src/combat/`; the conflict is between the binding task decision and the proposed implementation. The counterexample holds. Put fire mode in `weapons.ron` and test press/hold/release/repress for each gun.

Other corrections, checked against code and the task:

1. `TASK_FINAL.md` resolves Q4 to **B**: aiming caps movement at run speed. `PLAN.md` B3 changes only facing; `character/mod.rs::drive_characters` still calls `cfg.speed(intent.gait)`, so a sprint intent would remain 6.8 m/s while aiming. Add one aiming cap value to `assets/character/locomotion.ron` and apply it in the fixed movement system. Do not rely on the client changing gait: headless and future AI send intents directly.
2. `PLAN.md` §5 asks four already answered questions. The resolved answers in `TASK_FINAL.md` bind this slice: park center, primitive models, semi-auto pistol/shotgun, run-speed aiming cap. Remove those questions; no owner answer is pending.
3. GDD §4.1 says the head sensor is disabled in knockdown and death. T6 has `Dead` but no knockdown. The plan leaves the sensor ray-visible after death and merely rejects damage via `Without<Dead>`; a corpse still blocks a shot at a live target behind it and reports a head surface. Disable its `Hitbox` query membership on death and restore it on dummy reset/respawn. The plan's `dummy_life` also sets `Dead` with deferred `Commands`, so the same fixed tick can still see a target with `Health.current <= 0`; guard the health state in hit resolution before classifying a kill.
4. `PLAN.md` E6 calculates `tan(spread_deg)` even though the config names and C2 explicitly use degrees. Convert to radians before `tan`, and derive the displayed gap from the current FOV and window height. This is a visible but large HUD error: `tan(6)` is unrelated to a 6° cone.
5. The proposed `reload >= 0` validation allows zero, but C1 represents reload in progress as `reload_left > 0`; zero duration never transfers ammo. Require `reload > 0` or give zero an explicit instant-transfer path. The shipped values are positive, so the simpler strict validation is appropriate.
6. `recovery_delay > fire_interval` is presented as necessary for growth. It is only sufficient. Per-shot growth can exceed inter-shot recovery even with a shorter delay. Validate finite/nonnegative tuning and test the desired growth with the shipped SMG values; do not prohibit otherwise valid future tuning.
7. `PLAN.md` D8 writes damage before **every** Wasted update. That can mask the specific last-frame defect by leaving several messages in buffers and making the observed result depend on buffer rotation. Reproduce B1 with one message only on the final Wasted update, as the original probe did; assert full health both immediately after re-entry and after further fixed ticks. `flow/mod.rs` gates `apply_debug_damage` to `PlayingSystems`; `flow/wasted.rs::respawn_player` restores the same entity, so clearing the `DebugDamage` buffer on `OnExit(Wasted)` addresses the verified path.
8. `PLAN.md` D7's negative control removes `Sensor` **and** resets layers. That does not isolate which mechanism prevents Tnua from treating the head as ground. Use one change at a time, preserving the real scene and its query masks. `tests/common/mod.rs` already supplies the production `compose_sim`, fixed-clock harness, and `run_ticks`; new gates should use it.
9. `PLAN.md` F2's hard `Health == 75` runtime assertion assumes no stray second shot and exact aim despite a randomized cone. A 100 ms semi-auto press prevents a second pistol shot, but BRP aiming at a dummy can still miss or hit the head. Use a controlled close torso shot in the runtime scenario, confirm one magazine decrement and damage from the table; keep the deterministic exact-damage proof in the headless gate. Retry aiming before firing, not after observing the result.
10. The park is a design decision, not a proved clear firing lane. `world/city.rs::landmarks` takes the centroid of a generated park block; it does not guarantee a 25 m prop-free, flat shooting strip. Verify the seeded layout and spawned colliders before locking range placement. The plan's claim about all park props lacking colliders is not established by `world/city.rs`.
11. `PLAN.md` E2 says that when the cursor is uncaptured the input writer does nothing. That preserves a previously true `fire_held` and `AimIntent.aiming`; recapturing can resume fire. Explicitly set continuous intents false on cursor release, game state exit, and respawn, while leaving one-shot latches with a defined consume/clear policy.
12. `PLAN.md` B2's head geometry numbers are plausible but its validation should use body-space geometry explicitly: body center is feet + `float_height`, capsule top is `float_height + capsule_height/2` (1.80 m with shipped data), head center is 1.60 m and radius 0.35 m. Check an actual horizontal ray at head height against both colliders. Merely requiring `head_radius > capsule_radius` is an arbitrary stronger condition; the essential property is that the head can be the nearest hit in a useful aim band.

**Research verification.** The planned engine primitives are available for the pinned versions: Avian 0.7.0 [`SpatialQuery::cast_ray_predicate`](https://docs.rs/avian3d/0.7.0/avian3d/spatial_query/struct.SpatialQuery.html#method.cast_ray_predicate) returns the closest hit; [`SpatialQueryFilter`](https://docs.rs/avian3d/0.7.0/avian3d/spatial_query/struct.SpatialQueryFilter.html) filters by collider memberships and excluded entities; [`Sensor`](https://docs.rs/avian3d/0.7.0/avian3d/collision/collider/struct.Sensor.html) does not contribute mass. Bevy 0.19.1 [`Messages::clear`](https://docs.rs/bevy/0.19.1/bevy/prelude/struct.Messages.html#method.clear) exists. BEI 0.26.0 documents `SwizzleAxis::YXZ` for vertical mouse-wheel input in its [Binding API](https://docs.rs/bevy_enhanced_input/0.26.0/bevy_enhanced_input/binding/enum.Binding.html). Local pinned source and `bevy_brp_extras-0.22.6/src/mouse/button.rs` also confirm the proposed ray and mouse-button signatures. These sources support the API choices; they do not prove the game's hit geometry or schedule behavior, which need executable gates. The plan's community/blog citations about TPS and bloom are design references, not authoritative API evidence.

## 2. Updated understanding

- `crates/gta_sim/src/lib.rs::compose_sim` is the single production composition path. It loads and validates locomotion, health, respawn and city data, then installs physics, Tnua, character, world, player, combat and wanted plugins. `crates/gta_sim/tests/common/mod.rs::composed_app` calls that same function with `MinimalPlugins`, finishes and cleans up plugins, and controls fixed time.
- `character/mod.rs::character_components` builds the dynamic capsule and Tnua controller; no explicit collision layers exist yet. The body transform is `feet + float_height`. `drive_characters` runs in fixed time and currently maps camera-relative movement intent to speed and facing. `character/intent.rs` only has `MoveIntent`.
- `player/mod.rs::DebugDamage` is a buffered `Message`; its reader runs in `PlayingSystems`/`HealthSystems::Damage`. `flow/mod.rs` gates `PlayingSystems` on `GameState::Playing`; `flow/wasted.rs::respawn_player` restores health and removes `Dead` on the same player entity at `OnExit(Wasted)`.
- `combat/mod.rs` currently owns only health/armor pickups. `world/city.rs::CityLandmarks.park_center` is a park-block centroid. `world/test_area.rs` has a floor and obstacles for headless physics tests.
- Client input in `src/input/mod.rs` uses BEI in `Update`; camera look runs in `Update`, follow/collision in `PostUpdate` in `src/camera/mod.rs`. The camera's two shape casts currently use an all-layer filter excluding the player entity. HUD and visuals are client domains. `tools/qa/brp.py` has `send_keys`, `move_mouse`, and screenshot, but no mouse-button helper.
- GDD §4.1 and §13 T6 require two-ray hitscan, the `Hitbox` head sensor, spread, magazines, reload, weapon selection, pickups, dummies, aim camera/strafe, HUD and shot feedback. The task adds the B1 respawn regression and the four resolved choices above. T6 should not implement T7 knockdown or T13 full audio/juice systems.

## 3. Revised approach

Keep simulation ownership in `gta_sim` and presentation in the client. `AimIntent` and action latches are client-written data; headless tests set them directly. The weapon simulation runs in `FixedUpdate` under `PlayingSystems`; camera/UI/VFX/audio read its state and buffered `ShotFired`/`BulletTrace` messages in variable time. Apply damage through one `Health` rule and reject targets with `Dead` **or** `current <= 0`. Use the task's semi-auto/auto decision as a data field. Preserve one-shot range spawning on `Loading → Playing` and the existing city/test-area split.

For B1, clear only queued `DebugDamage` at the Wasted exit before the next Playing damage read; do not globally clear shot presentation messages. For head sensors, use a dedicated `Hitbox` membership and `Sensor`, prove Tnua ground exclusion in a headless scene, and remove/restore ray visibility with life state. Keep collision layer identifiers as code law, and every gameplay/feel tuning number in its GDD §12 RON file.

## 5. Risk areas

- **Schedule and input edges:** fixed time may run zero or multiple ticks per frame. Preserve one press once, stop held fire on cursor/state changes, and check message timing with an executable probe if observed behavior differs from the plan.
- **Ray/collision geometry:** head sensor must be nearest at head aim but never count as Tnua ground; the camera must ignore it; shooter child colliders must be excluded; walls must win the muzzle ray. Exact expected values are recomputed through the actual code path.
- **Death boundaries:** deferred `Dead` insertion leaves a brief zero-health state. Guard `Health.current` directly and hide the head query collider through death/reset; B1 messages must not survive Wasted re-entry.
- **Data and version drift:** strict loaders must validate every new field. Pinned Bevy/Avian/BEI/rodio source is the API authority. `rand_chacha` may be added to `gta_sim` only after the dependency feature tree remains renderer-free.
- **Park and presentation:** the chosen park centroid is not itself a verified clear lane. Verify seed 1 geometry. Audio, recoil, VFX, animation and readability are owner-run judgments; avoid synthetic gates that merely count effect entities as proof of feel.
- **Gate honesty:** the original geometry, reload and bloom examples are useful starting calculations, not immutable truths. Flip-RED each new or re-anchored gate against the mechanism it claims to catch.
